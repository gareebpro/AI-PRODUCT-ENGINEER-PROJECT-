pTechnical Requirements Document (TRD)
1. System Architecture

The CDSS follows a layered architecture:

Frontend Layer
API Gateway Layer
AI Backend Services Layer
ML Inference Layer
Data Storage Layer

2. Architecture Components
2.1 Frontend Layer Technology
	React.js
	HTML/CSS/JavaScript
	Features
		Symptom input form
		Free-text clinical input
		Diagnosis results panel
		Red flag alerts
		Treatment recommendation cards
		Patient history dashboard
2.2 API Gateway Layer Technology
	FastAPI
	Responsibilities
	Authentication
	Request routing
	Response formatting
	API communication
2.3 AI Backend Services
	Symptom Extraction Module
	Uses NLP/LLM APIs.
	Converts free-text input into structured symptoms.
	Red Flag Engine
	Rule-based logic.
	Detects emergency conditions.
	Uses NHM danger sign rules.
	Treatment RAG Module
	Searches NHM guidelines.
	Retrieves relevant treatment recommendations.

3. ML Inference Layer
	DDx Prediction Engine
	Algorithms
		XGBoost
		Random Forest Ensemble
	Output
	Top-5 diagnoses
	Confidence scores
	SHAP explanations
	Explainability
	SHAP values visualize feature importance.
	Provides transparent reasoning.

4. Data Layer
PostgreSQL

Stores:

Patient data
Visit history
Doctor information
Logs
ChromaDB

Stores:

NHM guideline embeddings
Treatment knowledge vectors
Model Store

Stores:

Trained models (.joblib)
SHAP explainers
5. Data Flow
Doctor enters patient information.
Frontend sends request to FastAPI.
NLP extracts structured symptoms.
Red Flag Engine checks emergency rules.
ML model predicts differential diagnoses.
RAG retrieves NHM treatment guidelines.
Results returned to frontend.
Patient data stored in PostgreSQL.
